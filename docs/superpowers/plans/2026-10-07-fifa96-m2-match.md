# FIFA 96 M2 child — playable match: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the match playable end-to-end — front-end → kickoff → control/kick/score → half/end → exit — windowed via SDL3 and deterministic headlessly.

**Architecture:** Extend the existing `fifa96_loader` libraries with the missing action/phase handler bodies (ported cluster-by-cluster from Ghidra, each cluster producing an FU doc), and wire them through `fifa96_match_run` in the engine. No new dependencies; the parent's platform ABI, surface, clock, and render chain stay frozen.

**Tech Stack:** C11 (`-Wall -Wextra -Werror`), CMake/CTest, SDL3 (installed), Python 3 tape tests, Ghidra MCP (read-only) for RE.

**Spec:** `docs/superpowers/specs/2026-10-07-fifa96-m2-match-design.md`

## Global Constraints

- C11, `-Wall -Wextra -Werror`; no warnings; `make check` green after every task (94 at start).
- Engine tests build under ASan/UBSan.
- Evidence-gated: every RE claim cites bytes/addresses/tool output; unprovable → numbered open leg; corrections append as errata, never rewrite prior map rows.
- Authoritative program `/FIFA96.EXE` (pass explicitly; `fifa96.exe` collides with the loader). Flat offsets need `+0x100000`.
- Ghidra is read-only for implementers; all Ghidra writes and commits are serialized by the controller.
- New docs use the next free FU numbers (FU137+), one per RE cluster.
- Determinism contract: the null backend is the regression source of truth; every render-path change re-pins its hashes with a documented reason.
- Commit style: `feat(...)`, `fix(...)`, `docs(fuNNN)`, `test(...)`, `chore(...)`.
- Original assets never committed; tests skip ISO-dependent cases when the ISO is absent.

## Gate G2 — Mechanics handlers

Each task in this gate: (1) bounded Ghidra pass over the cluster's dispatch rows in `/FIFA96.EXE`, appending a numbered FU doc; (2) extend the named library with the derived bodies, TDD against the dispatch semantics; (3) wire the engine's handler dispatch (`fifa96_match_handlers.c`); (4) per-task render/hash re-pin if the cluster reaches rendering. Every unimplemented row stays a numbered open leg, never a guess.

### Task 4: Dispatch mechanics and record machines

**Files:** Create `src/fifa96_engine/fifa96_match_handlers.c` / `.h`, `tests/test_engine_match_handlers.c`, `docs/ghidra/FU137_dispatch_mechanics.md`
**Produces:** `int fifa96_match_dispatch_action(struct fifa96_match_run *mr, uint8_t code);` `int fifa96_match_dispatch_phase(struct fifa96_match_run *mr, uint8_t phase);` backed by the two tables; `FUN_0007D9A4` argument staging and the `0x26`–`0x2C` installer arms per FU137.
**Test:** table-driven: every row resolves to a handler or an explicit "open leg" marker; staging writes the derived record fields; unknown code → `FIFA96_ERR_NOT_FOUND`.
