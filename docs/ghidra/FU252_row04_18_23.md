## 5. Shared fields (OL-83 territory) — the alias-aware split

### 5.1 `byte +0x8E` (the OL-83 split) — **more than one writer**

Fresh `search_instructions` finds the `+0x8E` byte **written** at
`0x6F90A`/`0x6F945` (`FUN_0006E8E8`), `0x79C8E`/`0x79CA0` (`FUN_00079C50`),
`0x7C051` (`FUN_0007BF20`) and `0x81BE3` (the `0x81Bxx` row). The frozen docs
say “`0x79C50` writes it at `0x79C8E`” and the engine models the *only* native
writer as the row-08 face — **that is incomplete.** Rows `04`/`18` read the byte
via `dword[+0x8B]>>24` (row 04: `0x7EE31`,`0x7EF70`,`0x7EF8F`,`0x7F003`,
`0x7F01C`), and the engine’s `mr->record.actor_type` is never written, so those
four read sites always see 0 in production. This materially widens OL-83 (the
reconciliation must repoint the readers to a byte with ≥4 native producers, not
a single face write).

### 5.2 `word +0x7D` (`face_word7d`) — producer is the face helper

Fresh `0x79C50`: `0x79C76 MOV word[ESI+0x7D], AX` (the `0xCD474` angle) and
`0x79C8E MOV byte[ESI+0x8E], AL` (`((word[+0x7B]+0x40)&0x3FF)>>7`). So **one
helper produces both the row-04 `+0x7D` and the `+0x8E` face octant** — the two
OL-72/OL-83 fields are the same face computation. Row 04 reads `+0x7D` at
`0x7EE5C`; the engine stages 0 (`s.face_word7d = 0`, handlers.c:2550).

### 5.3 `0x157A64` shared timer word

Zero-extended word added to the `dword[+0x89]` timer by rows `04`(`0x7EC23`),
`18`(`0x849C5`) and `23`(`0x82FA5`) alike. Producers in §4. The engine stages
the timer from `record.timer89` and never adds this word — a shared leg.

### 5.4 `0x1577FA` is a cross-row in-place cell

Written by the camera family **and by row 04** (`0x7EFE3`), read by rows 04
and 23. Any closure of row 04 must publish this write to the same cell row 23
consumes (they are not independent per-row copies).

### 5.5 Row-label note

The task brief files the row-23 `0x1577xx` inputs under **OL-69**; the frozen
FU-137 §6.1 dispatch table and FU-139 §10.8 file them under **OL-68** (OL-69 is
the row-06 leg). Flagged as a numbering discrepancy for the controller — do not
silently relabel.

## 6. Verdict

The three rows’ unmodeled surfaces are **not independent**: they share one
camera/track producer family (`0x1577xx`), one shared timer add (`0x157A64`),
and the face helper’s `+0x7D`/`+0x8E` pair. The OL-72/OL-68 “staged zero /
camera stand-in” convention is therefore **provably producer-attributable**:
every zeroed field has a named native writer. The OL-83 divergence is **wider
than documented** (≥4 `+0x8E` writers, so the engine’s never-written
`actor_type` is wrong for rows 04/18, not just row 08). All remaining work is
wiring declared inputs to existing producers; no new byte semantics are needed.
